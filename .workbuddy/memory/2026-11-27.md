## B2 修复：导出规格真正生效（2026-11-27 续 4）

整改清单 B2，R2 批次。根因：客户端 `api.ts:1070` 发 `resolution/fps/aspect`，`rpc.ts` 的 `timelines/render` 不读、`render-registry.start()` 不接；渲染只认 `timeline.exportFormat`（默认 1280×720@30）。

**关键设计决定：不持久化。** 导出条三个下拉是"这一次导出"的参数，不该顺手改写工程数据。所以 `start()` 收到 `exportFormat` 时构造副本 `{...timeline, exportFormat}` 去渲染——排队、`buildRenderSummary`、`recordSample` 读的都是副本，摘要里的规格自然正确，而 store 里的时间轴一字未动。附带加 `exportFormatOf(id)`，`render-retry` 按原规格重跑（否则失败一次重试就悄悄退回 720p）。

新增 `src/workbench/export-selection.ts`：`resolveExportFormat(base, selection)`。**口径 = 短边不变**（与 `derive-ratios` 一致）：横屏 2K=2560×1440，竖屏 2K=1440×2560。`portrait`(3:4) 必须用横版 `4:3` 转置得到——`DERIVABLE_RATIOS` 白名单里**没有 3:4**，别去加宽它（会影响多比例切片）。画面参数一变就丢 `bitrateKbps`（与 `estimate.ts` 同理）。

其他：
- `timelines/estimate` 也接三档（显式 width/height/frameRate 优先），值与 `timelines/render` 同源。
- 客户端导出条加 `[data-timeline-export-spec]` 实时标签，调**同一个** `resolveExportFormat`，所以显示的就是 ffmpeg 会输出的。文案 `exportSpecHint`，主题版本 `2026-11-27.4`。
- `docs/API-SURFACE.md` 更新 `timelines/render` / `estimate` / `render-retry` 三行 payload。

测试：新增 `tests/export-selection.test.ts`(10) + `tests/render-export-format.test.ts`(4)，`workbench-rpc-endpoints.test.ts` 加 3 例（假渲染服务，不依赖 ffmpeg，为此把 `makeHandler` 改成可注入 `render`），导出面板加 1 例。typecheck 通过；全量 **19 失败 / 196 通过 / 3 跳过 文件；26 失败 / 1352 通过 / 8 跳过 用例**，失败集合与 B1 后逐条一致，通过数 +18。
