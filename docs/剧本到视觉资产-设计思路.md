# 智能剧本分析引擎：剧本到视觉资产的设计思路

记录日期：2026-11-18
来源：「智能剧本分析引擎」界面截图讨论

核心逻辑：把非结构化的剧本，拆解成结构化的、可直接生成画面的视觉资产库。

## 1. 文本解析层：分步拆解，别让 AI 一把梭

- 注意：不要指望一个大模型一次性把角色、道具、场景、分镜全吐出来，一定会漏。
- 做法：严格按照界面上的「四步递进」。用 DeepSeek 这种长文本模型，配合固定 JSON Schema，分四次调用。先抽角色，再抽道具，再抽场景，最后基于前三者做分镜。

## 2. 实体隔离层：解决「画面穿帮」的根本

- 注意：道具需要纯白背景独立呈现，不出现场景/角色。
- 做法：所有提取出的「实体」（人、物、景）必须生成独立的提示词。分镜阶段，通过代码把这些实体的提示词拼接起来，而不是让 AI 在分镜里重新描述角色长相，否则必崩。

## 3. 提示词工程层：模版化 + 变量

- 注意：「十层完整描述法」和「动作链规划」不能是虚的。
- 做法：写死一套 Prompt 模版（PREFIX + AI 生成的变量 + SUFFIX）。比如角色默认带「Netflix 画质、左侧全脸 + 右侧三视图」，场景默认带「电影质感空镜」，这些约束用代码写死，不要让模型自由发挥。

## 4. 风格路由层：满足细分受众（竖屏短剧）

- 注意：「女频/男频分镜拆解」是个极好的卖点。
- 做法：建两套不同的 System Prompt。女频侧重「情感体验、CP 感、微表情」；男频侧重「爽点、权力关系、节奏感」。这决定了工具是否懂「短剧」这个垂直行业。

## 5. 工程架构层：前端轻，后端重

- 注意：上传 50MB 的 Word/PDF，还要实时进度，前端根本算不动。
- 做法：前端（Vue/React）只做上传和进度条展示；后端（Python/FastAPI）做文件解析，然后用 Celery 异步任务队列慢慢跑大模型。支持流式输出，让用户看到字一个个蹦出来，缓解等待焦虑。

## 一句话总结

核心壁垒不是大模型，而是中间那套「剧本到资产的拆解规则」和「防穿帮的提示词模版」。把这两点打磨好，就是一个极佳的短剧前期提效工具。
