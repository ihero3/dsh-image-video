## 一、主线：快速创作页面重做（R7 轮）

**目标**：把 `src/client/Workbench.tsx`（4,988 行、三模式共用）里的「快速创作」重做成一个
**一屏闭环**的创作页——提示词 → 参数 → 模型 → 生成 → 本次结果 ——不再靠上下滚动抵达动作与结果。

**交付物**
1. 一份页面规划书（信息架构 + 状态机 + 交互清单 + 与测试护栏的对应关系），先评审再动手。
2. 快速创作页新实现：从 `Workbench.tsx` 拆出独立目录（`src/client/create/` 或等价），
   专业工作流与时间轴保持现有挂载方式，**重做不牵连另外两个模式**。
3. 行为契约：现有 `tests/client-*.test.tsx` 里固化的 8 条行为，要么保留、要么列入"废弃"并在 PR 说明里写明为什么。
4. 门禁：五道门全绿；入口体积不超预算（v1.0.1 清场后入口占预算 96%，余量只够约 25 个文案 key，见下）。

**规划必须先回答的 4 个问题**
1. 右栏物理上限 **575px** 下，主视线保留哪 4 块？
2. 低频块（融合生图 / 提示词工坊 / 剧本分镜 / 模型能力卡 / 素材体检）放哪：抽屉、二级 tab、还是弹层？
3. 生成中与结果态怎么做到**零滚动**？（当前是"结果就地展示 + 自动滚入视口"）
4. 新增文案 key 量级多大？——入口必须整包注册 i18n 字典，**每 key ~100 B**，入口现占预算 **96%**
   （raw 67,114 / 69,600 · gzip 21,504 / 23,280）。超过 ~25 个新 key 就必须先把「入口只注册 2 个 key + chunk 延迟字典」做掉（见 §四 N5）。

## 三、待 owner 拍板的模块级删减（本轮必须先定）

仓库里**没有文件级死代码**（103 个源文件全部有引用）。真正的"不相干"只可能是**整块功能**。
删减与否、删多少，直接决定重做的工作量与风险：

| 候选 | 体量（源+测试） | 删掉的影响 | 建议 |
|---|---|---|---|
| 时间轴精剪（模型/渲染/字幕/导出面板） | `workbench/{timeline,edits,subtitles,srt,vtt,render,presets,derive-ratios}.ts` + 面板与 ~20 个测试 | 失去成片导出能力，"生成→成片"链断 | **保留**（产品核心闭环之一） |
| 专业工作流（画布 / 运行器 / 模板 / 运行记录） | `workflow.ts` 542 + `runner.ts` 483 + `WorkflowCanvas.tsx` 831 + `@xyflow/react` 依赖 | 画布与模板消失，chunk 体积大降（画布依赖是 chunk 主体） | **保留**（差异化的专业面） |
| 素材体检 / 导出历史 / 项目统计 / 配额清理 | `AssetHealthPanel` + 4 个 workbench 模块 | 诊断类能力消失，不影响创作 | 可后置（仍在"更多"里，不占主视线） |
| 项目包导出/导入 | `package.ts` 502 + 3 个测试 | 失去搬机器的能力 | 保留（成本低） |
| 配音应用层（计划/时长估算） | `voice.ts` 118 + `VoiceCard.tsx` 127 | 失去"字幕→配音计划"，等 TTS | 保留（已能零花费用） |

> 结论建议：**本轮不删任何功能模块**，只在"快速创作页"范围内重组 UI；
> 要瘦身就瘦**界面层**（拆文件、删死样式、延迟字典），不动领域层与宿主契约。
