## 一、这个页面是什么

右栏工作台（自带后端的插件）里的**第一个模式 tab**，和「专业工作流」「时间轴精剪」并列：
**一页之内完成「写提示词 → 调参数/模型 → 生成 → 立刻看本次结果」**，不需要切到画布或时间轴。
主区分两个标签页（「内容生产」/「提示词·分镜」）：内容生产上是本集工作区（剧本 → 分段 → 分镜）与两个模块，
提示词·分镜页负责选图逆向提取、编辑、存入本集提示词库并带入生成；旧「高级设置」抽屉已下线。

右栏**不是一个固定宽度**（宿主布局契约）：默认 = 视口 45%（1280 窗口下约 576px，插件内宽实测 575），
可拖范围 300 … min(视口 − 680, 视口 × 70%)，视口 <768 时右栏自动全屏。
设计基准是**宽度档位**（约 300 / 520 / 720 / 1000+），不是 575 一个数；三栏只在默认档放不下。

### 信息架构（默认档 ≈575px）

```
顶栏：剧集（Series）· 集 · 三模式 tab · 保存状态 / 版本 · 登录三视（登录后显示用户名/邮箱）· 帮助 · 工作台（列开关）
└ 左图标栏 42px：3 个模式 + 素材 / 任务 / 导出 / 技能库 + 帮助 / 默认值
└ 主区 paneCreate —— 两个标签页（data-quick-tabs）

   │   ├ ① 一键成片 PipelineCard（默认展开：剧本 / 模式 / 镜数 / 时长 / 严格资源 / 物料手选 / 编排 / 运行）

   资源 → 预览 → 素材 → 导出历史 → 任务
```

## 三、参数与默认值的关系

这一节回答「我明明没改参数，为什么界面里已经是 1024×1024 / 16:9 / 5 秒」。**三层不是一回事**：

| 层 | 位置 | 语义 | 代码位置 |
|---|---|---|---|
| **默认层**（当前生效参数） | **顶栏**「当前生效参数」7 字段 + 编辑 | 工作台覆盖 > settings 持久默认 > 工具内置默认，三层依次回落 | `src/runtime-defaults.ts`（`resolveDefaultsView` / `resolveDefaultsSources`）+ `src/index.ts` 装配 |
| **本次请求的显式参数** | 快速生成面板底部三只下拉 + 两只模型下拉 | **只有选了具体值才下发**；选「自动（跟随当前生效值）」= **不下发该字段**，由宿主按默认层决定 | `Workbench.tsx` `runGenerate`（`size` / `aspectRatio` / `duration` / `model` 都按 `...'' ? {} : {...}` 条件展开） |
| 回填 | 面板初始化 | 打开页面时用默认层**回填一次**，所以截图里的具体值可能只是回填，不是人改的 | `Workbench.tsx` 的 `F1` effect（依赖 `health`，只填「当前为空」的字段） |

7 个字段（`RuntimeDefaults`，与 `/image-video/defaults` 路由同一口径）：
`mediaMode`（composer 文本/图片/视频 tab，纯运行时概念）、`imageProvider`、`imageSize`（`宽*高`）、`imageStyle`、`videoProvider`、`videoAspectRatio`、`videoDuration`。
每个字段在顶栏都标来源：`override`（工作台/composer 改过）/ `settings`（来自设置）/ `none`（都没有，工具用内置默认）。

**顶栏没有「模型」字段**——这点最容易误判：

- 顶栏能改的是**服务商**（谁出图/出片），不是**模型**。
- 快速生成面板的「图片模型 / 视频模型」下拉是**本次请求**的 `model` 参数，覆盖的是**宿主自动路由**：
  图片按 `MODEL_FAMILY_RULES` 得到家族候选链（配置链 → 家族直连商 → threevideo 兜底），
  视频按项目约定**固定走 threevideo**（`resolveModelCandidates`，`src/runtime-defaults.ts`）。
- 所以「换模型」和「换服务商」是两个旋钮，一个在面板里（本次请求），一个在顶栏（默认层）。

### 已知坑（待修，已进「五」）

| # | 现象 | 根因 |
|---|---|---|
| K1 | 默认值后来改了，面板里早已回填的具体值**不跟着变** | `F1` effect 只在 `health` 变化（挂载、保存默认值后）时跑，且只填「当前为空」的字段；已填的不再覆盖。用户得手动选回「自动」才会跟随新的默认值 |
| K2 | 手动选成「自动」后，一旦保存过默认值，会被**重新回填**成具体值 | 保存默认值会刷新 `health`，effect 再次看到「当前为空」就回填——用户的「自动」被吃掉 |
| K3 | 截图/录屏里的具体参数值被当成「用户设置的」 | 回填是隐式动作，界面没有区分「值来自回填」与「值是人选的」的标记 |

## 四、本台账登记的已知问题

按严重度排。每条四段：现象 / 根因 / 修复状态 / 影响面。基线与修复状态均按提交 `b5b9bc1` 记录。

### P0-1 模型能力卡不可信（「已校验」是自述）—— 已验收关闭（2026-11-03，转「四·乙」L1 守护）

| 段 | 内容 |
|---|---|
| 现象 | 能力卡徽章恒亮「已校验」；服务商把生图/生视频模型关掉后，界面仍显示已校验；点卡片标题栏的刷新（`data-model-cards-reload`）只是重新拉同一份静态清单，什么都变不了 |
| 根因 | ① `src/media/model-catalog.ts` 的 5 张卡（当时；现已 6 张）是**静态硬编码**，每张写死 `verified: true`，它表达的是「我们曾经实测过」，不是「现在还能用」；② `models/catalog` 端点（`src/host/rpc.ts`）只返回 `modelCards()` + `catalogConsistencyIssues()`，**不做任何实时探测**；③ `panels/ModelCardsPanel.tsx` 的刷新调的就是这同一个端点，数据源不变，自然不变 |
| 修复状态 | **已修（2026-11-02）**：新增 `src/media/model-health.ts` 现场探测服务商模型目录（`GET {baseUrl}/models`），`models/catalog` 增 `live`（探测结果 + 逐卡 `available/missing/unknown`）与 `refresh` 入参（绕开 60s 缓存）；面板徽章改为以实时结论为准，失败时显示「无法校验 + 原因」，探测失败**永不抛错、绝不猜成可用**。静态 `verified` 仍表示「我们曾实测过」，与「现在可用」分开表达。**已验收（2026-11-03 用户实测）**：展开高级 → 模型能力卡 → 点 ↻，卡片照常保留、徽章与探测时间按服务商目录重新展示，"点了刷新什么都不变"不再出现；模型下拉展示也正常。此能力已锁定，见「四·乙」L1 |
| 剩余 | 只做了「服务商目录」这一路证据；「最近一次真实调用结果」还没接进徽章（任务账本里已有 model/status，可作为第二证据源；对应验收口径见 §五 第 2 项） |

## 六、创作资源库使用问答（2026-11-03 用户提问 → 结论）

> 这一节回答"这些控件到底是干什么的"，并记录同一轮修掉的交互问题。术语：**定妆参考图** = 资源的多张参考图，首图=底图。

| # | 问题 | 结论 |
|---|---|---|
| 1 | 「按名称筛选」筛选什么？ | 原来只匹配资源**名称**，备注（外观描述）搜不到 → 现在**名称或备注**都匹配；placeholder 改成「按名称/备注筛选」；空态区分「没有资源」与「筛选没命中（一键清空）」 |
| 2 | 「参考图（定妆照）」什么作用？ | 这是该资源的**参考图集合**（首图=底图/定妆照，其余=风格/脸参考）。融合生图、一键成片按**资源 id** 取这些图当参考 |

| 6 | 「填入融合表单」什么意义？建议提示词在哪改？ | = 把重绘计划给出的建议提示词填进「展开高级 → 融合生图」的提示词框并滚过去，接着点「融合生成」即可。建议提示词**不是手填字段**，由 `资源名称 + 备注（外观描述） + 参考图数量 + kind` 推导；所以「建议补一句外观描述」= 去资源行点**铅笔**把外观写进**备注**（2026-11-03 之前没有这个入口，现已补上） |
