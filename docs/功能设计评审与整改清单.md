## 〇、一句话结论

**单页改造到位，跨页链路断裂，主 CTA 层级不清。** 三个模块各自内部完整度不低（API、状态反馈、测试齐全），但作为连贯产品，用户走不完全程；且存在多处"控件有 UI 但操作不改结果"的假反馈，损害专业信任。

## 一、跨模块断点（P0，直接影响主流程）

### B1 · 剧本 → 画布同步的图必然校验失败

| 项 | 内容 |
|---|---|
| 现象 | 多镜头集点「同步到工作流」，生成的图整图校验失败，画布运行按钮禁用，用户无法从剧本进入可运行状态。 |
| 根因 | `src/workbench/storyboard-workflow.ts:76-78`：`link(previous, imageId)` 时 `previous` 是上一个镜头的 `videoId`（output `media`），而 `image-generate` 的 input 是 `text`。`PORT_ACCEPTS.text = ['any','text']`（`workflow.ts:464-469`），端口不兼容 → `validateWorkflow` 产出 `port-mismatch`（`workflow.ts:530-548`）→ `disabled={!validation.ok}`。 |
| 触发条件 | 集内镜头数 ≥ 2。单镜头集正常（只有 `image→video`）。 |
| 修复方向 | 二选一：① 镜头间不串联，每镜独立分支汇聚到 `preview`（每镜 `video→preview`，端口 media→media 成立）；② 在镜头间插一个 `creative-input`/`script` 文本节点承接。方案①更符合"逐镜独立生成"的语义，且保持幂等。 |
| 验证 | 新增纯函数测试：`buildEpisodeWorkflow` 产出图经 `validateWorkflow` 必须 `ok === true`（≥2 镜头）；真机同步后运行按钮可点。 |
| 状态 | **✅ 已修（2026-11-27）**：采用方案①，删除 `previous` 串联，改为每镜 `image→video` 后各自 `video→preview`；边数不变（n 镜 2n 条），幂等不变，预览节点落在分支纵向中点。验证见 §7。 |

> 附带的语义问题：`preview` 节点没有执行器（`runner.ts:24` 只有 image/video），所以即便校验通过，"跑完"也只产出图片/视频路径，不是成片。见 B5。

### B2 · 导出规格是假控件

| 项 | 内容 |
|---|---|
| 现象 | 时间轴导出条选 2K / 60fps / 方形画幅，成片完全不变。 |
| 根因 | 链路三处断点：① 客户端 `src/client/api.ts:1070-1075` 把 `resolution/fps/aspect` 放进请求体；② 宿主 `src/host/rpc.ts:2321-2336` 的 `timelines/render` 只透传 `priority/retryTransient/thumbnailAtMs/subtitleFormat`，**不读**这三个字段；③ `src/media/render-registry.ts:536` 的 `start()` 签名也不接受；真正编码取 timeline 快照的 `exportFormat/frameRate`（`render.ts:109-125,194-245`）。 |
| 误导点 | 测试 `tests/client-export-panel.test.tsx:67-79` 只断言请求体含这些值，未断言宿主按值渲染 → 测试绿但功能坏。 |
| 修复方向 | 贯通一条：`api` 下发 → `rpc` 读 `resolution/fps/aspect` → `renders.start` options 扩展 → `render.ts` 用它覆盖 timeline 默认值；或若产品决定不支持，则**移除三个下拉**，不要留假控件。 |
| 验证 | 集成测试：同一 timeline 分别以 480P/2K 渲染，断言 `ffprobe` 输出分辨率不同；不得只测请求体。 |
| 状态 | **✅ 已修（2026-11-27）**：新增 `src/workbench/export-selection.ts`（档位 → `exportFormat` 纯函数，短边口径与多比例切片一致）；`rpc.ts` 的 `timelines/render` 解析三档并换算，`render-registry.start()` 增加 `exportFormat` 覆盖（走**副本**，不改存储），`render-retry` 按原规格重跑；`timelines/estimate` 同口径。导出条新增实时规格标签 `[data-timeline-export-spec]`，与宿主共用同一换算函数。验证见 §8。 |

### B3 · 「只跑这个节点」实际跑全图

| 项 | 内容 |
|---|---|
| 现象 | 画布检视器点「只跑这个节点（含下游）」，整个工作流都执行了。 |

| 验证 | 测试：3 节点线性图只跑中间节点，断言上游未执行、下游按语义处理。 |

### B5 · 「跑出结果」≠「交付成片」

| 项 | 内容 |
|---|---|

| 判断 | 这属于**能力边界诚实暴露**（错误信息明确），不算欺骗，但与画布"后期与交付"分组给用户的预期不符。 |

## 三、主次功能层级（P1）

### 3.1 三页主按钮规格三套并存（二次复核新增，P1）

同一应用里三个"下一步"用了三种类名、三种尺寸，主次信号无法跨页迁移：

| 页面 | 主按钮 | 类名 | 实测高度 | 样式来源 |
|---|---|---|---|---|
| 剧本生成 | 生成剧本 | `iv-btn--action--primary` | **34px** | `modern-theme.ts:107-108` |
| 时间轴精剪 | 导出成片 | `iv-btn--acc iv-btn--lg` | **42px** | `modern-theme.ts:67-68,63` |
| 专业工作流 | 运行整图 | `iv-btn--acc iv-btn--sm` | **26px** | `modern-theme.ts:92,87`（F2 已修） |

后果：**画布页最重要的操作是三页里视觉最小的按钮**，且落入 `.iv-btn` 基础灰底（`modern-theme.ts:58`），与旁边 14 个工具按钮完全同级。用户在画布上找不到"该点哪个"。

修复方向：收敛为单一主按钮原语（建议 `.iv-btn--acc`），三页统一；`iv-btn--primary` 要么补定义、要么全量替换。顺带定一条纪律：**一个 pane 内只允许一个 `.iv-btn--acc`**。

| 模块 | 当前 P0 | 问题 | 建议 |
|---|---|---|---|
| 剧本生成 | `生成剧本` / `开始分段` / 每段`生成分镜脚本` | 三个 `iv-btn--action--primary` 同屏（分别位于 `PipelineCard.tsx:292-302`、`EpisodeWorkspace.tsx:1778-1787`、`:1248-1258`），用户不知道"下一步"是哪个 | **已实施（2026-11-27，见 §3.3）**：加三步进度条，按真实进度只让「下一步」是主色 |
| 专业工作流 | 运行整图 | 唯一 CTA 用无效类名（F2），被 14 个等权工具按钮淹没；节点库 15 项拆 5 组是好的 | **F2 已修（2026-11-27，见 §11）**：落回 `iv-btn--acc`；运行组 1px 分隔线（D4）仍待做；空态模板卡按钮升为 CTA 尺寸仍待做 |
| 时间轴精剪 | 导出成片 | 三页里层级最清楚（`Workbench.tsx:4709-4731` 唯一 `--acc --lg`），但导出参数无效（B2）损害信任 | 先修 B2，层级无需大改 |

**已做对的降级**（保持）：剧本 `⋯` 溢出菜单（同步/导出/导入）+ 段内高级设置 + 分集剧本 details；画布检查器抽屉 + 日志抽屉；时间轴辅助折叠区（逐段预览/配音/多比例）。

### 3.2 顶栏本身没有主次（2026-11-27 已实施）

三 pane 改造只做了面板内部，顶栏是一行直排 20 个控件：品牌 → 剧集（标签+下拉+改名+删除+新建输入+创建）→ 集（同上）→ 模式导航 → 保存态 → 工具。实测 **1440px 就已经溢出被动换行**，模式导航落到第二行最左边，而「创建剧集」的黑色主按钮成了整条栏最重的元素。

已改为两层：**对象行**（品牌 / 剧集 / 集 / 保存态 / 工具）+ **视图标签栏**（四个模式贴着内容，选中项 = 加粗文字 + 实色图标 + 2px 下划线 + 轻底色）。同步收敛：`创建` 平时为普通按钮、输入后才升主色；改名/删除降到 72% 不透明度；「新建剧集」与当前剧集之间加竖线分组。细节与逐档降级见 `CHANGELOG.md`「顶栏重排」。

仍未做（不影响本次结论）：三页主按钮的**尺寸**仍是三套（34 / 42 / 26px）；F2 只把画布运行按钮换到真实主按钮类，统一尺寸属后续打磨。

### 3.3 剧本页首屏三个同级主按钮（2026-11-27 已实施）

**原问题**：`生成剧本`（`PipelineCard.tsx:292-302`）、`开始分段`（`EpisodeWorkspace.tsx` 分段选择器行）、每段的 `规划分镜`（`EpisodeWorkspace.tsx` 段动作行）三处都是 `iv-btn--action--primary`，同屏三个实心主色，用户看不出「下一步」是哪个；生成成功后也没有任何指向下一步的信号（F16）。

**改法**——不删按钮，而是让权重跟着**真实进度**走：

1. 新增步进条（`Workbench.tsx` 的 split 分区顶部，`data-script-steps`）：写剧本 → 分段 → 生成分镜。状态由当前集数据判定，不看点击历史：
   - 第一步完成 = 剧本正文非空 **或** 已有分段（有分段说明已过第一步，避免"有分段却提示去写剧本"的倒退）；
   - 第二步完成 = `segments.length > 0`；第三步完成 = 任一分镜有镜头。
2. 「下一步」= 第一个未完成的步骤。**只有它对应的按钮是 `--action--primary`，其余降为 `--action--soft`**；三步全完成时没有实心主按钮，提示改去画布 / 时间轴。
3. 步进条带一行动作提示（"点「开始分段」把剧本拆成段…"），点任意步骤滚到对应区块并闪一下（复用 `scrollToPane` 的 `iv-pane--flash`，同样防御 jsdom 没有 `scrollIntoView`）。
4. 生成剧本成功后自动把视口带到「开始分段」（`requestAnimationFrame` 一帧后跳），补上 F16 的断点。

**为什么不是"首屏只留一个主按钮"**：三个动作都需要随时可用（改完剧本要能重新生成），直接降级会让用户找不到。按进度换主色既保住可用性，又始终只有一个实心。

**实现要点**：
- `PipelineCard` 新增 `emphasis?: 'primary' | 'soft'`，缺省 `primary`（单独渲染时行为不变，`client-pipeline-card.test.tsx:86` 仍成立）；
- `EpisodeWorkspace` 新增 `activeStep?: 0 | 1 | 2 | 3`，缺省时两个按钮都保持 `primary`；
- 新增 `tests/client-script-steps.test.tsx`（7 例）锁住：四种进度下的权重、唯一实心、"有分段不倒退"、点按滚动目标、分镜锚点缺失时退回分段。

**验证**：`pnpm run typecheck` 通过；该文件 7 例全过；全量 vitest 与改动前同口径（19 失败文件 / 26 失败用例，均为 ffmpeg 渲染、版本一致性、skills 等既有失败，通过数 1324 → 1331 即新增 7 例）。
