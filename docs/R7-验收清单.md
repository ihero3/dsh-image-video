# R7 验收清单（真机执行）

> Round 7 改的全是**看得见的东西**：字号、按钮尺寸、告警颜色、面板边框。

## 2. 强调层级自动检查（R7-6 新增）

```bash
DSH_WEB_URL=http://localhost:5173 pnpm run check:emphasis
```

会跑 **10 条硬断言**（双主题各一遍）+ 打印软提示。逐条含义：

| id | 断言 | 失败说明什么 |
| --- | --- | --- |
| `scale-btn` | lg ≥ 28px 且 lg > 默认 > sm | `.iv-btn--lg` 没生效，或有人把主按钮改回 sm |
| `cta-shadow` | lg 有 `box-shadow` | 强调只剩尺寸，窄栏下压不住 |
| `scale-font` | lead ≥ 14 > title > strong > body | 字号令牌被改乱 / 中间档被删 |
| `pane-title` | ≥ 13px 且 > body 11px | 面板标题又回到"和正文同字号" |
| `create-title` | ≥ 14px 且 > pane-title | 主创标题没有压住其他面板标题（W1 失效） |
| `prompt-height` | 实高 ≥ 80px | 提示词又被 `.iv-input{height:23px}` 压回单行条 |
| `busy-opacity` | ≥ 0.9 | busy 按钮还在吃 `disabled` 的 42% 灰（"在跑"看起来像"坏了"） |
| `busy-ring` | `::before` 宽 10–14px | 旋转环太大撑破 20px 按钮，或太小看不见 |
| `block-bar` | `border-left-width = 3px` | blocking 级丢了左侧红条 |
| `block-color` | warn 与 err 的 `color` 不等 | block 又与软警告同色了 |

**软提示**（不判失败，需要你判断）：每个可见 pane 里 `.iv-btn--lg` / `.iv-btn--acc` 的数量。
计划 §2 定的是"每屏 W1 ≤ 1、W2 ≤ 3"，但"什么算一屏"得人判——脚本只把数字摊开。

> 已知：快速模式把"生成 / 融合 / 提示词工坊 / 故事板"都装在一个 `paneCreate` 里，
> 所以该 pane 的 accent 计数必然偏多。**这不是 bug**，是"一个 pane 承载多个子工作区"的结果；
> 真正要看的是每个子区块（`.iv-sub` / `.iv-card`）里有没有两个抢戏的主按钮。

## 3. 对比度（沿用 R6-4，但本轮有新增色）

```bash
DSH_WEB_URL=http://localhost:5173 node scripts/check-contrast.mjs
```

本轮新增/变更的语义色重点看这几处：

- `.iv-chip--err`（block 的芯片）—— 红底白字，双主题都要 ≥ 4.5:1
- `.iv-notice--block`（左红条的拦截条）—— 文字不能因为红条变亮而掉对比
- `.iv-meta--err`（block 的命中建议）—— 小字，必须 4.5:1（不是 3:1，14px 不适用 large-scale）
- `.iv-pane--quiet` 的面板标题 —— 底变浅/变深后，标题不能掉到 4.5:1 以下

| 区域 | 预期变化 | 原因 |
| --- | --- | --- |
| 主创提示词 | 明显变高（≥80px，原来是 23px 单行条） | R7-2 |
| 融合 / 故事板 / 分镜的文本框 | 变高（`rows` 生效） | R7-2 全量修复 |

> 如果看到**只有这几处之外**的变化，说明有非预期的样式泄漏，先查再往下。

## 5. 只能人眼判的三项（这轮的核心）

### 5.1 眯眼测试（squint test）

把截图缩到 25% 或眯起眼看，问三个问题：

1. 第一眼看到的是不是**提示词输入框 + 生成按钮**？
2. 九个面板的**标题**能不能连成一条可读的骨架？
3. 有没有**第二个东西**在抢第一眼？（有 → W1 不唯一，回去砍）

### 5.2 三秒测试

给没看过这个工具的人看 3 秒，然后问："这个界面最主要让你干什么？"
答不出"写提示词然后生成" → 主次仍然不分。

### 5.3 380px 窄栏（最容易翻车的地方）

把右栏拖到最窄（约 380px），重点看：

- [ ] `lg` 按钮（30px）会不会压扁文字或换行错位
- [ ] 时间轴导出行的 `lg` 按钮与旁边 `sm` 的"取消"是否有明显错位感
- [ ] 提示词 80px 高在小屏上是否挤压到生成按钮（应仍有间距）
- [ ] 四个 `iv-pane--quiet` 面板的边框减淡后，**边界是否还能分辨**（分不清就调回 30% 减淡）

## 6. 生成中 / 阻塞态（需要真实状态，不能只靠探针）

探针只能证明"类名挂上后长这样"，证明不了"业务里真挂上了"。这两条要手动触发：

- [ ] **生成中**：点生成，按钮应显示**旋转环 + 满不透明**（不是灰掉）。四个长任务各试一次：生成图片、融合运行、时间轴导出、故事板规划。
- [ ] **阻塞态**：输入会触发内容合规的提示词，应看到**红色芯片 + 左侧红条 + 加粗文字**，且生成按钮不可点。
- [ ] 两个主题各看一遍（block 的红色在深色主题下最容易糊）。

## 7. 失败了怎么定位

| 现象 | 先看哪 |
| --- | --- |
| `check:emphasis` 报 `prompt-height` | `.iv-create textarea.iv-input{min-height:80px}` 是否还在；`iv-textarea` 类是否掉了 |
| 报 `scale-btn` | `.iv-btn--lg` 是否被后续规则覆盖（搜 `height:2` 的重复定义） |
| 报 `busy-*` | `.iv-btn--busy` 规则顺序是否在 `:disabled` 之后 |
| 报 `block-color` | `.iv-chip--err` 是否仍用 `var(--iv-danger)` |
| 逐条硬断言都过但看着还是"平" | 那就是**留白**问题，不是尺寸问题——看 §5.3 与计划 §7 |
