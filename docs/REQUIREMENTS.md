## 1. 总目标与边界

### 1.1 目标（V1 可用闭环）

在**不改动 Harness 主布局**的前提下，把 `dsh-image-video` 从"对话里调工具出图/出片"扩展成桌面客户端内的**视频创作工作台**，占据右侧工作区（框架图：左=左侧导航/工作区/插件/自动化任务；中=Agent 对话区，交互不变；右=dsh-image-video 工作台），提供三个模式并共用一个项目、素材库、资源库、任务区与预览区。工作台不引入第二个产品名：文档、tab 标题、`kind`、`id`、RPC 命名空间一律沿用 `dsh-image-video` / `image-video`（见 §14-D1 已定）。

1. **快速创作**（现有链路，`已有` + 适配）：composer 媒体 tab → 注入 → `generate_image` / `generate_video` → 结果登记进项目素材。
2. **专业工作流**（`本方案实现`）：右栏展开区里的 **flow 节点流**画布，节点连边、按图执行真实生成/渲染，`planned` 节点禁跑。
3. **时间轴精剪**（`本方案实现`）：以素材引用为单位的轨道模型 + 字幕轨 + ffmpeg 导出 MP4。

- `R-BND-1` 当前右栏工作台的形态必须是**客户端插件注册的右栏 tab**（审计 §4.1、§9），不得以 iframe 嵌外部站点、不得改右栏核心布局。
  - 验收：卸载插件后右栏 tab、RPC、事件、后台任务全部撤销；现有文件树/浏览器/终端等 tab 不受影响。
- `R-BND-2` 产品代码只生长在 `dsh-image-video` 包内（宿主半边 + 客户端半边），不新增第三个私有包；桌面端沿用现有私有插件装载名单（审计 §10.1、§9 结论）。
  - 验收：`apps/desktop` 的 `LOCAL_PLUGIN_BUNDLES` / `PRIVATE_PLUGIN_NAMES` 不需要新增产品名即可装上带 client 半边的本插件。
- `R-BND-3` 本地优先：第一版不建设产品自有云端、不要求登录团队账号；素材与项目落在本机（审计 §2.2）。
  - 验收：断网状态下可打开已有项目、浏览素材、编辑节点与时间轴；只有真正生成/渲染时才需要网络。
- `R-BND-4` **禁止假执行**：`预留接口` 能力（对口型、换脸、配音合成、高光解说/混剪）可以出现在节点表与模板里，但必须有 `availability` 标记、按钮禁用、不得伪造成功、不得进入自动拓扑执行（计划 §6.2）。
  - 验收：对 `planned` 节点的"运行"入口为禁用态且有原因提示；全量运行遇到 `planned` 节点必须停下来报错而不是跳过。
- `R-BND-5` 现有快速创作链路（composer 媒体 tab → `/image-video/defaults` → `agent/pre-step` 注入 → 工具 → 对话卡片）**必须保持可用**，本次扩展不得改变其交互（审计 §7 模式 A）。
  - 验收：不打开工作台、只用对话完成一次出图与一次出片，行为与改动前一致（对话卡片、尺寸文案、生成模式文案不变）。

## 2. 用户与场景

| 角色 | 场景 | 关键需求 |
|---|---|---|
| 桌面用户（多数） | 对话里直接出图/出片，不改参数 | `R-QCK-1`、`R-ENT-4` |
| 创作者 | 在右栏展开区搭 flow：脚本 → 分镜 → 生成 → 发布素材 | `R-FLW-1..8`、`R-MED-1..6` |
| 剪辑者 | 把多条素材放上时间轴、加字幕、导出成片 | `R-TML-1..7` |
| 运营/复现者 | 打开别人的项目包，素材与节点布局完整恢复 | `R-PRJ-5`、`R-PRJ-6` |

> 现有桌面端的媒体入口（composer 的 `文本 / 图片 / 视频` 三 tab）与右侧工作区（文件/浏览/终端/预览）均已存在，本次是**在既有界面里新增一个 tab 与一套业务层**，不是新造一个前端。

## 3. 入口与布局需求

- `R-ENT-1` 右栏新增工作台 tab（对外名沿用插件名 `dsh-image-video`，见 §14-D1 已定）：**用自己的 `kind`**（如 `dsh-image-video-workbench`）与全局唯一 `id` 注册 tab 类型，内容以该 `id` 为 key 挂在 `sidebar.right.pane.tab` 座位上，并提供 guide entry（entry id 亦须唯一）。扩展点本身 `已有`（审计 §4.1）。
  - 约束（Harness 实测）：一个 kind 最多一个 builtin + 一个 extension；`priority` 缺省是 `extension`，**声明成现有 builtin 的 kind 会静默截获它的 body 与 title 座位**（座位按定义自己的 `id` 派发），因此不得复用 `files`/`browser`/`terminal`/`text`/`plan`/`subagentchat` 等既有 kind；重复 `id` 直接抛错。
  - 验收：tab 出现在右栏 tab 列表；打开后标题/图标/locale/主题跟随 Harness；禁用或卸载插件后 tab 消失且无残留占位，既有 tab 未被 shadow。
- `R-ENT-2` 工作台顶部固定三段信息：**项目名称**、**保存状态**、**模式切换**；布局与框架图一致（项目名称/保存状态在标题区，模式在当前模式工作区域之上）。
  - 验收：无项目时入口为"新建/选择项目"；有项目时可直接改名；保存状态有 `已保存 / 保存中 / 有未保存改动 / 保存失败（含原因）` 四态。
- `R-ENT-3` 三个模式：`快速创作` / `专业工作流` / `时间轴精剪`；切换模式**不丢失**当前项目、素材引用与画布/时间轴状态（计划 §9 阶段 1、阶段 6）。
  - 验收：在 A 生成一张图 → 切到 C 能直接引用它 → 切回 B 画布节点位置不变。
- `R-ENT-4` 左栏与中间对话区**零变化**：不新增左栏入口、不改对话卡片协议；工作台与对话是并列的两个面（框架图"保持原有对话交互"）。
  - 验收：左栏项、对话输入区、消息卡片与改动前逐像素无新控件（人工对比 + 右栏外无新增 DOM）。
- `R-ENT-5` **右栏展开**：窄宽度下工作台自身做窄布局，需要大画布时用右栏**既有**的 fullscreen 呈现——`autoFullscreen = 视口宽 < 768px`；手动入口是面板右上角控件或快捷键 `primary+alt+Enter`；宽度约束由 `ui-layout` 决定（右栏最小 300px、中间最小 400px、右栏最大占比 0.7）。切换 fullscreen **不重挂载** tab。计划 §10 的"复用右栏 fullscreen"即指此。
  - 验收：窗口拉到最窄时仍能完成"选素材 → 预览 → 提交任务"；展开态下画布可平移缩放，退出展开后节点位置与编辑状态不变；**不自己实现第二套全屏机制**。
- `R-ENT-6` 首次进入有 guide entry（空态引导：新建项目 / 从对话快速创作 / 打开项目包），空态不报错、不空白。
  - 验收：全新用户（无项目）打开 tab 看到三条入口；每条都能走到下一步（新建项目成功 / 引导到 composer / 打开项目包对话框）。

## 4. 项目与持久化需求

- `R-PRJ-1` 项目是工作台的根实体：`id / name / version / createdAt / updatedAt`（审计 §8）。
  - 验收：新建项目后重启 Harness，项目仍在列表里且名字与创建时间不变。
- `R-PRJ-2` 自动保存 + 显式保存：编辑（改项目名、加入素材、改节点图、改时间轴）后自动落盘；保存状态可见（`R-ENT-2`）。
  - 验收：改项目名后 2 秒内状态变 `已保存`；写入失败时状态为 `保存失败` 并给出可操作原因（路径/权限）。
- `R-PRJ-3` 记录级版本与迁移：每条记录带 `version`；打开旧项目先迁移再交给业务层（审计 §8 版本策略）。
  - 验收：仓库内含一个旧版本 fixture 项目，打开后自动迁移成功且原文件不改写（写新版本）。
- `R-PRJ-4` 引用完整性：删素材前扫描资源/工作流/时间轴引用；删资源前扫描工作流/时间轴/项目默认绑定，被引用时拒绝或要求先替换（审计 §8）。
  - 验收：被时间轴引用的素材点"删除"给出"被 N 处引用"并可跳转；强制删除后相关轨道不出现悬空引用。
- `R-PRJ-5` 项目包导入/导出（阶段 8）：导出 `项目记录 + 素材 + 资源 + 工作流 + 时间轴` 的本地包；导入时可选择"合并素材"或"仅结构"。
  - 验收：导出 → 换一台机器/换一份 `DSH_HOME` 导入 → 素材可预览、节点布局与时间轴一致；缺素材时明确列出缺失项而不是静默丢。
- `R-PRJ-6` 项目状态可恢复：崩溃/强杀后重开，未完成的任务标记为"中断"而不是永久"运行中"；画布与时间轴无未保存改动丢失。
  - 验收：任务运行中 `kill -9` 桌面进程，重开后任务区显示 `中断（可重试）`，画布节点数与位置与崩溃前一致。
- `R-PRJ-7` 快速创作不强制建项目：对话生成结果先落在默认项目，用户在对话卡片上选择"发送到工作台"或"放入时间轴"（审计 §7 模式 A）。
  - 验收：连续对话生成 2 张图 + 1 段视频后打开工作台，3 个素材在默认项目里可预览，且没有重复登记。

## 5. 模式 A：快速创作（保留 + 登记）

- `R-QCK-1` 现有链路原样可用（见 `R-BND-5`）。`已有`
- `R-QCK-2` 生成结果落盘时**同时登记**项目媒体素材引用（`assetId`），并记录来源任务与生成参数。`本方案实现`
  - 验收：一次图生图完成后，工作台素材区出现该素材，元数据含尺寸、模型、参考图来源；同一任务重复登记不产生第二条素材。
- `R-QCK-3` 引用了角色/场景/道具/音色资源时登记"资源使用记录"，供资源库显示"被哪些素材用过"。
  - 验收：用角色资源生成一段视频后，资源详情页列出该视频素材；删除该资源前提示被引用。
- `R-QCK-4` 对话卡片提供回工作台的入口（"发送到工作台" / "放入时间轴"），但**不改变**卡片现有信息与播放行为。
  - 验收：点击"放入时间轴"后切到模式 C，该素材成为一条视频轨 clip，`inMs/outMs` 为整段。

## 6. 模式 B：专业工作流（flow 节点流，右栏展开区）

- `R-FLW-1` 画布只负责交互（节点位置、连线、选择、缩放平移、适配窗口），**不承担**执行、参数校验、调度、持久化（计划 §6.1）。
  - 验收：断网时画布仍可编辑、保存、重开；画布维度状态只有一个 `WorkflowRecord` 事实源，UI 瞬时选择不入库（计划 §10 风险表）。
- `R-FLW-2` V1 节点集按计划 §6.2 的表提供：`creative-input / script / storyboard / asset-reference / resource-reference / motion-track / image-generate / video-generate / preview / publish-asset`；`lip-sync / face-swap / voice-synthesize` 为 `planned`；`subtitle / render` 为 `本方案实现`。
  - 验收：节点面板能看出每个节点的 `runnable` / `planned`；`planned` 节点可放进画布并保存，但运行按钮禁用且有原因。
- `R-FLW-3` 图校验与拓扑执行：宿主校验图（必填参数、类型匹配、环检测），按拓扑顺序执行，节点产出写入 `WorkflowRunRecord.nodeRuns`（计划 §6.3）。
  - 验收：含环的图提交时被拒并指明回路；合法图运行后每个节点有状态、耗时、输出素材 ID。
- `R-FLW-4` 节点参数可编辑并有默认值；`video-generate` 复用现有 `generate_video` 参数语义（模型/比例/时长/分辨率/首尾帧/参考视频/compare），不另立一套协议。
  - 验收：画布上跑一次图生视频，产出的视频与在对话里调 `generate_video` 的结果在参数层面等价（同一模型、同比例、同素材引用）。
- `R-FLW-5` 运行可观测：节点级进度、失败原因、重试；已成功节点的输出可复用（不重复付费调用）（计划 §5.5）。
  - **实现口径**：按节点实际工具参数算 sha256 指纹缓存产物；命中且文件仍在即复用（`cached: true`，不调外部）；换参数 / 文件被删 / `refresh=true` 时真重跑；缓存上限 200 条
  - 验收：运行到第 3 个节点失败后重试，前 2 个节点不重新调用外部 API（用日志或任务记录证明）。
- `R-FLW-6` 运行记录可追溯：`WorkflowRunRecord` 持久化，能回看每次运行的图快照与产出素材。
  - 验收：连续运行同一张图两次，任务/运行区有两条独立记录，各自带当时的节点参数。
- `R-FLW-7` 模板：至少内置 3 个可用模板（如"文案→分镜→图→视频"、"图片→视频→字幕→渲染"、"参考视频复刻"），模板实例化后可直接跑。
  - 验收：任一模板在只填提示词与素材的情况下能跑完（`planned` 节点不进模板）。
- `R-FLW-8` 画布的展开/收起：画布在右栏 tab 内可用；进入展开态后画布占据主要面积，退出后回到工作台布局（`R-ENT-5`）。
  - 验收：展开态下节点操作（拖拽/连线/删除）与普通态行为一致，节点位置在两种态之间保持。

## 7. 模式 C：时间轴精剪与导出

- `R-TML-1` 时间轴保存的是**媒体素材引用 + 剪辑指令**，不是视频字节（审计 §7 模式 C 的 `tracks` 结构）。
  - 验收：时间轴 JSON 里只有 `assetId`/`startMs`/`inMs`/`outMs` 等引用与参数，无 base64/内联字节；项目体积不随剪辑动作线性增长。
- `R-TML-2` 三类轨道：`video` / `audio` / `subtitle`；视频轨 clip 支持 `trackResourceId + trackParams`（轨迹模板实例化）。
  - 验收：一个项目含三条轨、≥3 个 clip 时可保存重开并完整恢复；字幕轨可编辑文本与时间。
- `R-TML-3` 预览：可在不渲染的情况下按时间轴顺序预览（拼接口径与最终导出尽量一致，差异需在 UI 说明）。
  - 验收：两段素材首尾相接的预览切换点与导出成片切换点偏差在可接受阈值内（阈值与测法写进测试）。
- `R-TML-4` 字幕：字幕轨可导入/编辑文本与样式，导出时由 ffmpeg 烧录（阶段 5）。
  - 验收：导出成片含可读字幕；关闭烧录开关时导出无字幕且时间轴不丢字幕数据。
- `R-TML-5` 导出 MP4：创建时间轴快照 → `RenderService` → ffmpeg 渲染，产出 `RenderRecord` 与输出素材；支持分辨率/帧率选择。
  - 验收：导出成功产出可播放 MP4，时长与轨道总长一致（±1 帧）；同一快照重复导出不改动原素材。
- `R-TML-6` 导出进度与失败可操作：进度可见、可取消；失败给出可操作原因（ffmpeg 缺失、磁盘不足、素材丢失、编码不支持）。
  - 验收：把 ffmpeg 从 `PATH` 移走后导出，UI 显示"未找到 ffmpeg"并提供安装/配置入口，而不是抛栈或静默失败。
- `R-TML-7` ffmpeg 运行时策略必须明确交付口径（审计 §3.5、§10 风险表）：开发机复用外部 ffmpeg；发布桌面版前决定 sidecar 打包或安装检测。
  - 验收：见 `TASKS.md` 中该任务的判定；发布前必须有"打包版能导出"的真机证据，或明确列为已知限制。

## 8. 媒体素材与创作资源库

- `R-MED-1` 媒体素材：`AssetRecord`（`id/projectId/kind/uri/name/mimeType/bytes/width/height/durationMs/sourceTaskId/tags`），文件不可变、按新素材 ID 迭代（审计 §8）。
  - 验收：同一素材被两处引用时删除其一会提示；素材文件物理不可变（重复导出生成新文件）。
- `R-MED-2` 素材来源统一：对话生成、工作台生成、外部导入、导出成片都进同一素材库（审计 §6.1 素材与资源分层）。
  - 验收：四个来源各产生一个素材，素材列表按 `kind` 过滤可用。
- `R-MED-3` 创作资源库：`ResourceRecord` 覆盖角色/场景/道具/品牌/风格/音色；资源由素材组成，可被节点与时间轴引用（审计 §6.1）。
  - 验收：建一个角色（含参考图）→ 在 flow 的 `resource-reference` 里可选到 → 生成出的视频登记了该资源使用记录。
- `R-MED-4` 轨迹资源：`TrackResourceRecord`（主体资源 + 关键帧 + 备注），生成阶段转为提示词约束并诚实说明"模型是否严格遵循由服务商决定"（审计 §2.1）。
  - 验收：绑定轨迹的生成请求里能看到轨迹转成的约束文本；结果元数据记录所用轨迹。
- `R-MED-5` 素材预览：图片/视频/音频在预览区可播放/查看，缩略图与时长正确；大文件不阻塞 UI。
  - 验收：≥200MB 的参考视频在预览区不冻结界面（交互响应 <200ms），播放走本地引用而非 data URL。
- `R-MED-6` 删除与回收：删除素材/资源走 `R-PRJ-4` 的引用守卫；有独立的"回收站/回收站清空"或明确的不可恢复提示（二选一，见 §14-D2）。
  - 验收：删除动作有明确后果说明；勾选"同时删除文件"时才删除磁盘文件。

## 10. 与 Agent 的协作与工具面

- `R-AGT-1` 工作台的业务能力**通过插件自己的 RPC 命名空间**暴露给客户端，不复用别的插件的命名空间（审计 §4.3）。

### D3 结论：ffmpeg 走"安装检测 + 允许覆盖路径"，不打包 sidecar（2026-10-16 定）

- **结论**：宿主启动后**按需探测**本机 ffmpeg（`DSH_FFMPEG_PATH` → PATH → 常见安装位置），并检测版本与 H.264/AAC 编码器；缺失/无权限/缺编码器都给机器码 + 一句话下一步（`T5-4` 已落地）。
- **为什么不打包**：① 每个平台 60–100 MB 级别，远超客户端 548 KB 的量级；② 私有插件只复制 `package.json` / `cordis.patch.yml` / `lib`（见 §14-14），sidecar 二进制得另立打包规则；③ 授权与更新面成本高于收益。
- **代价（如实记录）**：非开发机需要用户自己装 ffmpeg；因此**导出前必须探测**，并在 UI 上给出安装指引，而不是让导出先失败再猜。
- **复核触发条件**：若将来要在"零配置"的封闭环境分发，再回来评估 sidecar（届时按平台分片 + 校验和）。

**判定规则**：任务完成的前提是该任务覆盖的需求条目验收全部通过；任一条 `本方案实现` 的需求没有对应任务，视为计划缺项，必须补进 `TASKS.md`。
